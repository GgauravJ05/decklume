Decklume vs frontend-slides

Both are free, MIT-licensed Claude Code skills that output a single HTML presentation. This is where they differ.

frontend-slidesDecklume
How design is controlledProse guidance and style recipes the model translates by handDesign tokens, 29 tested layouts and themes written as code
StoryAsks for your contentYou approve an outline with an assertion headline per slide
Style previewsThree separate files, title slide onlyYour title and content slides in three themes, on one page
Themes12 presets and 34 bold style recipes13 complete themes, every layout designed and tested
MotionEntrance animationsEntrances, step-by-step builds and Magic Move transitions
ChartsNot includedBar, horizontal bar, line and donut charts in SVG
VerificationAdvice to review screenshotsAutomated QA gate with contact sheet, tested in CI
PresentingSpeaker notes passed to a hostPresenter window with notes, timer and next slide
PDF exportScreenshot images; about 20 MB for 18 slides (per its docs)Vector with selectable text; 1.1 MB for 32 slides
PowerPoint importPython script: text, images and notesPure Node: adds bullet levels, tables, grouped shapes and native chart data
OutputOne self-contained HTML fileOne self-contained HTML file
LicenseMITMIT

When frontend-slides may suit you better

If you want the widest range of bold, one-off visual styles, its 34-recipe template pack is a great source of ideas, and it needs no Node scripts at all.

When Decklume may suit you better

If you want every slide type designed consistently, a story you approve first, and a deck that has been checked in a browser before you present it, Decklume is built for that.
