# Phase 3: SEO for the site and for shared decks

## Goal

Every page on `ggauravj05.github.io/decklume/` has a title and description within
search-result limits, the 13 near-identical demo decks stop competing with the
theme pages, and any deck a user shares shows a proper link preview.

## Context

- The site is generated by `scripts/build-site.mjs` from templates in
  `scripts/site/` (`layout.mjs` holds the `<head>`, `pages.mjs` / `home.mjs` /
  `content.mjs` hold page copy). Never edit `site/` by hand; rebuild it.
- Decks get their `<head>` from `skills/decklume/scripts/build.mjs` (around
  line 236). They already emit `description`, `og:title`, `og:description` and
  `og:type`. They emit `og:image` only when the deck's front matter sets
  `image`, and they never emit a canonical link.
- `site/demos/<slug>.html` are the showcase lecture in each theme, so 13 pages
  repeat the same text. `site/examples/*.html` are the example decks.
- `site/sitemap.xml` and `site/robots.txt` are generated too.

## Findings from the audit (re-measure first; they may have drifted)

| Priority | Finding |
| --- | --- |
| HIGH | Demo and example decks have no canonical tag, and none are in the sitemap. 13 demos repeat one lecture. |
| HIGH | 21 of 22 page descriptions exceed 160 characters (longest 259). |
| HIGH | 15 page titles exceed 60 characters; `/examples/` is 92. Theme titles can drop "for Claude". |
| MED | Shared decks have no preview image unless the author sets one. |
| MED | The home page loads Google Fonts as a render-blocking stylesheet. Unmeasured. |

Measure titles and descriptions with:

```bash
node -e '
const fs=require("fs"),p=require("path");
const walk=d=>fs.readdirSync(d,{withFileTypes:true}).flatMap(e=>e.isDirectory()?walk(p.join(d,e.name)):e.name.endsWith(".html")?[p.join(d,e.name)]:[]);
for(const f of walk("site")){const h=fs.readFileSync(f,"utf8");
const t=(h.match(/<title>([^<]*)/)||[])[1]||"",d=(h.match(/name="description" content="([^"]*)/)||[])[1]||"";
if(t.length>60||d.length>160||!/rel="canonical"/.test(h))console.log(t.length,d.length,/rel="canonical"/.test(h)?"":"no-canonical",f)}'
```

## Work (one commit each)

1. `test(site): fail on long titles, long descriptions and missing canonicals`.
   Add a test in `tests/` that builds or reads `site/` and asserts title ≤ 60,
   description ≤ 160, and a canonical on every page. It fails at first.
2. `fix(site): shorten page titles` in the templates.
3. `fix(site): shorten page descriptions` in the templates.
4. `feat(build): canonical link option for decks`. Add a `canonical` front-matter
   key to `build.mjs`; emit `<link rel="canonical">` when set.
5. `fix(site): point each demo's canonical at its theme page`.
6. `feat(site): list example decks in the sitemap`, with their own canonicals.
7. `feat(build): default preview image for shared decks`. Without an `image` key,
   fall back to something real, for example a cover frame rendered by
   `export.mjs`, written next to the deck. Decide with the user; a generic
   Decklume image is the cheap fallback.
8. Run Lighthouse on the home page (Chrome DevTools MCP `lighthouse_audit`, or
   `npx lighthouse`) and fix only what it flags. Fonts: preload or
   `media="print" onload` swap if it matters.
9. `build(site): rebuild pages, sitemap and demos`.
10. Optional: `Organization`/`SoftwareApplication` JSON-LD on the home page,
    `BreadcrumbList` on theme pages. Only schema that matches visible content.
